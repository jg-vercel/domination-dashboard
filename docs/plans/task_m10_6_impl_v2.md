## 구현 순서

1. AuthControl을 별도 컴포넌트로 분리하고 OAuth/Redis 설정을 독립적으로 전달합니다. 일반 사용자에게 환경변수 입력을 요구하지 않습니다.
2. 일시적 세션 조회 오류에는 새로고침, 만료·무효 세션에는 Google 로그인 동선을 제공합니다.
3. keepalive는 최초 표시, 표시 중 1시간 간격, 탭 복귀·온라인 복귀 시 갱신합니다. 이벤트 최소 간격은 5분이며 숨겨진 탭은 갱신하지 않습니다. 요청을 중첩하지 않습니다.
4. 401은 갱신을 중단하고 router.refresh로 UI를 동기화합니다. 5xx/네트워크 오류는 다음 주기에 재시도합니다. cleanup은 타이머·이벤트를 해제합니다.
5. session API는 확정된 무효/만료에만 cookie를 삭제합니다. 503/502는 보존합니다.
6. UI 상태 조합, 갱신 이벤트·실패·정리, API cookie 갱신/보존/삭제, 시간 경과 세션 회귀를 테스트합니다.

## 기대 결과

로그인 정보는 서버 암호화 저장소에 유지되며 설정 누락·일시 장애·로그인 필요가 구분됩니다. 기존 TTL 정책을 유지합니다.

## 운영 반영 추가 승인 (2026-09-14)

- 작업지시자 “반영해”에 따라 Git 반영, Production 환경 설정 및 배포·HTTP 검증까지 승인되었습니다.
- Google Client ID/Secret 및 Redis URL/Token은 기존 Secret 값을 재입력·노출하지 않고 target을 Preview+Production으로 확장합니다.
- 운영에 처음 등록하는 `APP_SESSION_SECRET`은 별도 난수로 생성하고 이후 고정 유지합니다. Preview의 키는 변경하지 않습니다.
- Production `APP_BASE_URL`은 `https://domination-dashboard.vercel.app`으로 설정합니다.
- 변경 파일만 커밋하고 원격 push는 `devel`로 수행합니다. 기존 사용자 미추적 파일은 제외합니다.
- Vercel CLI 명시적 `--prod` 배포 후 메인 화면·인증 시작·세션·리전 등을 확인합니다.
- Google redirect URI 허용 여부도 가능한 범위에서 확인하고, 실계정 인증은 사용자 브라우저 검증 사항으로 남깁니다.
